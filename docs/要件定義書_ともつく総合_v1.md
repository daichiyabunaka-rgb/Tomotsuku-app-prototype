**バージョン**: v1.0（ドラフト）
**対象スコープ**: 総合版「ともつく！」v1（ハブ横断＋UGCハブ。提案008 Phase 1〜3）
**作成日**: 2026年11月
**ステータス**: 要件確定待ち（法務レビュー項目あり）
**参考**: 提案008「総合版とUGCハブ化」。v1本文は第12弾「ゲーとも！」の要件定義書を母体としており、ハブ登場以前の記述（アプリ固有の例）は「ゲーとも！」を例にとった読み替えで扱う。

## 1. 概要

### 1.1 目的

趣味仲間同士を、**本人の素顔ではなく趣味・中身ベース**でマッチングする「ともつく！」シリーズの総合版として、以下を実現する。

1. ハブ横断（Phase 1）: 1本のアプリで内蔵12ハブ（飯/犬/釣り/猫/コス/走り/キャンプ/音楽/銭湯/スポーツ/雀/ゲーム）を切り替えて使う。募集ジャンル・興味カテゴリ・近くの施設タグ・業態・ゆずりあいボードはすべてハブ設定（HubConfig）で決まる
2. 一般ユーザー同士：今から・近くで趣味仲間を探して一緒に遊ぶ（募集は時限付き）
3. ビジネスユーザー：地図連携・DMで、近隣の趣味仲間に店舗を知ってもらい来店へつなげる
4. コミュニティ・イベント: 誰でも作成・参加できる
5. 需要収集（Phase 2）: 「次のハブのリクエスト」「機能のリクエスト」ボードでユーザー投票（1人1票）を集め、「次に何を作るべきか」をデータで決める
6. UGCハブ制作（Phase 3）: ユーザーが「ハブをつくる」ウィザードで新しい趣味ハブを設定ベースで申請し、運営審査を通ると全ユーザーのハブ一覧に表示される（Roblox型UGC）

### 1.2 コンセプト上の設計原則

| 原則 | 内容 |
|---|---|
| 本人の素顔画像禁止 | プロフィール画像は「ゲーム画面・コントローラー・大会風景に関連する画像のみ」許可。本人の素顔がメインの画像はアップロード不可（モデレーションで拒否・削除） |
| 施設ルール・近隣配慮 | 音量・深夜の練習は施設・近隣のルールの確認を常に案内。無断使用・深夜騒音の募集は禁止文言で排除 |
| 恋愛目的禁止 | 利用規約で「恋愛・異性交際目的の利用」を明示的に禁止。違反は BAN 対象 |
| 金銭取引禁止 | ゆずりあい・交換は無償の譲り合い・物々交換のみ。ゲームグッズの売買・オークション的な利用は禁止。賭博的な利用も禁止 |
| 時限性 | 募集は期限付き（1〜3時間）。期限が来たら自動消滅。「今から」感が出会い系化を防ぐ |
| 距離の粗表示 | 正確な位置は非公開。「〜1km / 1〜3km」のような大ざっぱな距離のみ表示 |

### 1.3 前提と未確定事項（法務レビュー必須）

| 項目 | v1 の対応 | 備考 |
|---|---|---|
| 出会い系サイト規制法 | サービスの実質を「ゲーム仲間探し」とし、規約・モデレーションで異性交際目的利用を排除 | 弁護士による非該当性確認を必須とする。素顔画像禁止・一言メッセージ制は非該当性の根拠になる設計 |
| 未成年利用 | **v1 は18歳以上のみとする**（シリーズ各弾と同じ） | 夜間帯のゲームセンター利用や保護者の同意を踏まえ18歳以上を推奨。未成年対応はv2以降で法務確認の上検討 |
| 安心して利用できる運営 | ゲームセンターの営業時間・料金体系は法令・施設規則の確認を常時案内。適正な施設利用を推奨。無断使用の募集は通報・削除対象 | イベントの主催責任・免責規約の整備 |
| 迷惑防止条例（客引き） | ビジネスユーザーの営業・AI接客はアプリ内完結とし、押しつけのない設計（一斉配信はしない）。オプトアウト手段を常時提供 | 個別自治体への確認は開発中に実施 |
| 個人情報保護法 | 位置情報・嗜好データの第三者提供は「匿名加工統計」に限定 | 店舗ダッシュボードには集計値のみ表示 |
| 受け渡しの安全 | ゆずりあい・交換の受け渡しはゲームセンターの入口前・駅前広場など人目のある場所を前提とし、個人の自宅住所等を記入させない案内。金銭授与・送金を伴う取引は禁止 | トラブルを想定した免責規約の整備 |

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| 一般ユーザー | 無料で利用する趣味人（個人。リアルでもネットでも可）。趣味仲間を探す側 |
| ビジネスユーザー | 有料プランで登録する店舗・事業者・個人営業主（ゲームセンター、ゲームショップ・ホビー店、ゲームセンター、カードゲーム・ボードゲーム店、ゲームカフェ、レンタルスペース運営など） |
| 募集（Recruitment） | ユーザーが近隣に向けて時限で発信する「参加者募集」（今から一緒にプレイ / 大会・イベント参加 / 交流・オフ会）。投稿から1/2/3時間後に自動消滅 |
| 応募（Application） | 募集への参加申請。主催者が承認するとグループチャットが生成される |
| コミュニティ | 常設のグループ（ゲーム仲間の会、eスポーツ観戦部、ゲームセンター常連会等）。誰でも作成可、参加自由（承認制も選択可） |
| イベント | コミュニティまたは個人が企画する日程付きの集まり（定例ゲーム会、大会参戦、攻略講習など） |
| 施設検索 | 現在地近くの立ち寄り施設（ゲームセンター・公民館・集会所）を一覧表示し、Googleマップ（標準URL）で開ける機能。ワンタップで「その施設で募集」も可能 |
| ゆずりあい・交換 | 使わなくなったゲームグッズを近隣で無償でゆずる・探す・交換するボード。金銭取引は禁止 |

## 4. ペルソナ

### 一般ユーザー
- 20代〜50代、ゲームセンターやネット対戦を楽しんでいる。誘い合えるゲーム仲間が少ない・引っ越して環境が変わった
- 「今夜一戦したいが相手が足りない」「大会に参戦したいが一人だと不安」
- 恋愛マッチングアプリには抵抗がある（恋愛目的でない人）
- 買い替えで余ったソフトやコントローラーがあるので、誰かに無償でゆずりたい

### ビジネスユーザー
- ゲームセンター・ゲームスクール・ゲームセンター等の経営者
- 「閑散枠・平日に利用を増やしたい。近くのゲーム好きとの接点が少ない」「AI接客で問い合わせ対応と、地図から来店への導線を強化したい」
- 月額数千円〜1万円程度の予算感で、新規客よりも「リピーター・常連コミュニティ」を増やしたい

## 5. 機能要件

### 5.1 会員登録・認証

| 要件 | 内容 |
|---|---|
| FR-1-1 | SNS 認証（Apple / Google / LINE）。v1 では電話番号認証を必須としないが、通報対策としてアカウント単位のレート制限を実装 |
| FR-1-2 | 登録時の必須入力：ニックネーム、年代（10歳刻み表示、生年非公開）、性別（非公開も選択可）、居住エリア（市区町村レベル）、興味カテゴリ（複数選択。**ハブごとに定義された初期セット＋ユーザー自由追加**）、自由記述（140字、「ステータス」） |
| FR-1-3 | **アイコンは写真アップロードまたは提供アイコンセットからの選択**。アップロード画像は **本人の素顔** を AI 顔検出で自動審査する方針（本開発）。**ゲーム画面・コントローラー・大会風景の画像の投稿は許可（推奨）**の案内を常時表示 |
| FR-1-4 | 年齢確認：生年月日を入力させる（18歳以上チェック用）が、プロフィールには公開しない |
| FR-1-5 | 退会：アカウント削除時のデータ保持期間（アクティブデータ即時削除、バックアップ90日）を規約に明記 |

### 5.2 近くの仲間・募集（コア機能）

| 要件 | 内容 |
|---|---|
| FR-2-1 | 「募集をかける」：以下を指定して募集を発信できる |
| | - ジャンル（今から一緒にプレイ / 大会・イベント参加 / 交流・オフ会） |
| | - タイトル・本文（例：「今からゲームセンターで一戦を立てます。初心者も歓迎です」） |
| | - 条件設定：性別指定（任意）、人数上限、ジャンル・浴場の言及（自由記述） |
| | - 有効期限（1 / 2 / 3 時間、期限切れで自動消滅） |
| | - 待ち合わせ場所：施設名（「近くの施設」タブからワンタップで設定可） |
| FR-2-2 | 「近くの人」リスト：現在地から粗い距離（〜1km / 1〜3km / 3〜5km / 5〜10km）で、近くのアクティブな募集・ユーザーを一覧表示。並び替え：距離×新着 |
| FR-2-3 | 検索：ジャンル、キーワード、距離、興味カテゴリでフィルタ可能。「探す」タブからは近くの店舗（業態・店名で検索可）と近くのコミュニティ・イベント（距離近い順）も辿れる |
| FR-2-4 | **近くの施設検索（本アプリの特別機能）**: 現在地周辺の実在の立ち寄り施設を OpenStreetMap（Overpass API）から取得し、近い順に一覧表示（距離バンド、営業時間）。対象は**ゲームセンター（leisure=amusement_arcade）・公民館・集会所（amenity=community_centre）**のみ。**民間の飲食店（cafe等）・公園（leisure=park）は一覧に含めない**。名称のない施設は対象外。Google Maps（Places API）との連携は本リリース時のオプションとして見送り。各施設は「Googleマップで開く」（座標指定の標準URL）でGoogleマップに遷移する。「この施設で募集」ボタンで待ち合わせ場所を初期設定した募集を作成できる。利用マナー・ゲームセンターのルール確認の文言を常時表示 |
| FR-2-5 | 募集は同一ユーザーが同時に1件まで（スパム防止） |

### 5.3 応募・交流

| 要件 | 内容 |
|---|---|
| FR-3-1 | 応募：募集詳細から「参加したい」ボタンで応募。一声メッセージ（任意、140字） |
| FR-3-2 | 主催者は応募一覧から承認／却下。承認人数が上限に達したら募集は自動的に締切 |
| FR-3-3 | 承認されたメンバーでグループチャットが自動生成。参加者はその後も辞退可能 |
| FR-3-4 | 1:1 のダイレクトメッセージは募集への応募経由でのみ送れる設計（いきなり DM される対策） |
| FR-3-5 | 万一に備えた安全機能：ブロック／通報は一般ユーザー間と同一水準。初対面の集合・受け渡しは「ゲームセンターの入口前」「人目のある場所で」行うよう投稿時に案内 |

### 5.4 プロフィール・中身重視設計

| 要件 | 内容 |
|---|---|
| FR-4-1 | 趣味・嗜好の表現をリッチにする（ジャンル、好み、こだわり）を「ステータス」としてマイページに表示 |
| FR-4-2 | 過去の参加募集数、参加者からの評価（「また一緒に演奏した」ボタン式、v1.5 実装）を表示 |
| FR-4-3 | ブロック／通報：非表示、通報（理由入力）。通報数が閾値超過で自動凍結 → 人力審査 |

### 5.5 ビジネスユーザー（v1.5）

| 要件 | 内容 |
|---|---|
| FR-5-1 | 店舗登録：店舗名、業態（審査対象: ゲームセンター、ゲームショップ・ホビー店、eスポーツ施設運営、カードゲーム・ボードゲーム店、ゲームカフェ、レンタルスペース運営、その他）、住所、営業時間、写真（店舗・設備の画像 OK。**本人の素顔写真禁止は一般ユーザーと同じ基準**） |
| FR-5-2 | **AI接客（有料機能）**: ビジネスユーザーは店舗情報を登録するだけで、AI（LLM）が来店前の質問対応・案内（卓の空き状況、大会、料金、営業時間等）を行う |
| FR-5-3 | **地図連携**: 近くの店舗をアプリ内マップ（OpenStreetMap タイル、APIキー不要）にピン表示。各店舗は「Googleマップで開く」（標準URL）。本開発で Google Maps SDK に移行し経路案内まで表示 |
| FR-5-4 | 効果測定: AI接客の応答数・来店導線・閑散時間のアクセス推移を店舗ダッシュボードに表示 |
| FR-5-5 | 課金：月額制（ライト／スタンダード／プレミアム）。決済は Stripe / RevenueCat 等の標準的な手段を利用 |

### 5.6 コミュニティ・イベント

| 要件 | 内容 |
|---|---|
| FR-6-1 | コミュニティ作成：誰でも可（名前、説明、カテゴリ、公開／承認制、地域）。ゲーム仲間の会、eスポーツ観戦部、ゲームセンター常連会等 |
| FR-6-2 | イベント：コミュニティに紐付けて日程・集合施設名・募集人数を設定し、参加受付 |
| FR-6-3 | ビジネスユーザーも一般ユーザーも同じコミュニティに参加可 |
| FR-6-4 | コミュニティ一覧（参加中・未参加とも）は**近い順にソート**する。コミュニティ自身の位置情報は持たず、メンバー・主催者の中で最も近い人までの距離で近さを定義する |

### 5.7 ゆずりあい・交換（ゲームグッズ）

| 要件 | 内容 |
|---|---|
| FR-7-1 | 登録: 「ゆずる」（give）「探す」（wanted）「交換」（trade）を、グッズの特徴（ソフト・コントローラー等の名前・状態）、受け渡し希望地域や施設名、状況・受け渡し方法、**写真1枚（任意。ギャラリー/カメラ）**を入力して登録できる。位置は登録時の現在地（geohash）のみを持つ。写真はグッズの写るものとし、本人の素顔画像がメインの写真は投稿不可（一般のアイコンと同じ基準） |
| FR-7-2 | 検索: 近くの登録を**距離近い順**に一覧。ゆずる／探す／交換で絞り込み可。投稿者へのDM導線を同画面に持つ |
| FR-7-3 | 解決: 投稿者は「完了にする」を設定でき、完了は一覧から表示しない |
| FR-7-4 | 法務・安全設計: **金銭取引は本アプリでは行わない**（売買・オークション・送金を禁止。無償の譲り合い・物々交換のみ）。受け渡しはゲームセンターの入口前・駅前広場など人目のある場所を前提とし、自宅住所など個人を特定できる情報の記入を禁止案内 |

### 5.8 ハブ（総合版の核心・Phase 1）

| 要件 | 内容 |
|---|---|
| FR-8-1 | ハブとは「ともつく！」シリーズ1アプリ相当の趣味ドメイン。募集ジャンル3種・興味カテゴリ・施設検索タグ（Overpass）・ビジネス業態・ゆずりあいボードの有無を HubConfig として持つ |
| FR-8-2 | 内蔵12ハブ（tomotsuku=ホーム + meshitomo/inutomo/tsuritomo/nekotomo/costomo/hashitomo/campotomo/ototomo/yutomo/supotomo/janotomo/gametomo）をアプリ内で切替できる。切替で AppConfig.activeAppId が変わり、Supabase は app_id フィルタで分離されたデータを参照する |
| FR-8-3 | ホームハブでは全ハブのユーザー・募集が混在して表示される（「ともつく！全体」の賑わい検証用） |
| FR-8-4 | マイページに「現在のハブ」を表示し、タップでハブ選択シートを開く |

### 5.9 リクエストボード（Phase 2）

| 要件 | 内容 |
|---|---|
| FR-9-1 | 「次のハブのリクエスト」: 趣味名と説明を投稿し、他ユーザーが賛同（1人1票・取り消し可）できる。賛同数の多いものが次に作るハブの候補になる（status: open/approved/launched/rejected） |
| FR-9-2 | 「機能のリクエスト」: 機能名と説明を投稿し、特定ハブ向け（hub_id）または全体向け（null）に賛同を集める（status: open/planned/shipped/rejected） |
| FR-9-3 | 投稿・投票は Supabase（hub_requests / hub_votes / feature_requests / feature_votes。RLS: 自分の投票のみ insert/delete）に保存される。未接続時はモックで動作 |

### 5.10 ハブをつくる（UGC・Phase 3）

| 要件 | 内容 |
|---|---|
| FR-10-1 | 5ステップのウィザード（基本情報 → ジャンル → 興味カテゴリ → 施設タグ/業態 → 確認）。最小構成（名前・説明・興味カテゴリ1つ）で申請できる |
| FR-10-2 | 申請時に「顔写真目的でない」「金銭取引・賭博でない」「公序良俗」の3チェックを必須とする |
| FR-10-3 | 申請は hub_configs に status='pending' で登録（app_id は `hub_` + タイムスタンプ36進。RLS: 本人の pending 行のみ insert/update/delete）。運営が審査し、承認（status='approved' + services 登録）で全ユーザーのハブ一覧に即時表示される |
| FR-10-4 | 承認済みUGCハブは起動時に fetchApprovedHubConfigs で読み込み、ハブ切替・募集・施設検索まで内蔵ハブと同等に機能する。ただしゆずりあいボード（exchangeTable）は持たない |

## 6. 非機能要件

| 項目 | 要件 |
|---|---|
| プラットフォーム | iOS / Android（Flutter）。Web 管理画面（モデレーション用） |
| 位置情報プライバシー | 位置情報は端末側で geohash（精度レベル5〜6程度）に変換して送信。サーバーには生の緯度経度を保持しない。退会時に即時削除 |
| セキュリティ | TLS 通信、認証トークン（短期＋リフレッシュ）、パスワードレス（SNS認証） |
| 応答性能 | 募集の一覧取得は P95 200ms 以内（キャッシュ活用）。プッシュ通知は P95 30秒以内 |
| 拡張性 | 趣味カテゴリ（第1弾:飯とも、第10弾:スポとも、次弾:ゲーとも等）はマスタデータ化し、アプリ再リリースなしで追加可能 |
| モデレーション | AI 審査（**本人の**素顔画像検出、禁止ワード、違法走行募集の検知）＋人力審査ワークフロー。通報 → 凍結 → 審査の SLA 48時間 |
| アナリティクス | 登録 → 募集投稿 → 応募 → 成立（チャット生成） → 実参加（チェックイン）→ リピートのファネル KPI を計測 |

## 7. データモデル（概要）

```
users (id, auth_provider, nickname, birth_decade(非公開), gender, gender_public,
       city_geohash, role [general|business], status, created_at)
profiles (user_id, app_id, bio, interest_ids_json,
          participation_count, rating_score, icon_media_id)
media (id, owner_user_id, media_type [icon|store_photo], moderation_status)
recruitments (id, host_user_id, app_id, genre_id [daycamp|overnight|gearmeet],
              title, body, capacity, expires_at, meetup_name,
              status [active|fulfilled|expired|cancelled], created_at)
applications (id, recruitment_id, applicant_user_id, message,
              status [pending|accepted|declined], created_at)
rooms (id, recruitment_id, type [group], created_at)
room_members (room_id, user_id, joined_at, left_at)
messages (id, room_id, sender_user_id, body, created_at)
communities (id, name, description, category_id, visibility, owner_user_id, created_at)
community_members (community_id, user_id, role, joined_at)
events (id, community_id, title, starts_at, location_name, capacity, status)
parts_exchanges (id, poster_user_id, kind [give|wanted|trade], item_description,
                 area_name, detail, photo_path, location_geohash,
                 closed, created_at)
spots (id, name, place_type [camp|caravan|hut], google_place_id,
       location_geohash, features_json, last_checked_at)  -- 本開発: Google Places / OSM から取得
stores (id, business_user_id, name, industry_type, address, geohash,
        business_hours_json, created_at)
ai_concierge_logs (id, store_id, user_id, question, answer, created_at)
reports (id, reporter_user_id, target_type, target_id, reason, status, reviewed_at)
blocks (blocker_user_id, blocked_user_id, created_at)
subscription_plans (id, name, price, features_json)
subscriptions (id, store_id, plan_id, status, period_start, period_end)
```

設計メモ：
- 募集の期限切れは毎分のバッチで `status` を `expired` に更新。クライアントは `_expires_at` を見て表示制御も行う（二重防護）
- 施設は外部データ（Google Places / OSM）を `spots` に同期し、`google_place_id` で「Googleマップで開く」URL を組み立てる
- ゆずりあい・交換は geohash 先頭4桁一致（約20km四方）を「近く」とする
- 距離検索は geohash プレフィックス照合で実装し、生の緯度経度での距離計算はクライアント側で行わない

## 8. 画面フロー

```
[初回起動]
  オンボーディング（コンセプト説明 + 恋愛目的禁止・公道マナーの同意）
    → 認証（プロトタイプ: メール）
    → プロフィール入力（ニックネーム / 年代 / 興味カテゴリ / 紹介 / アイコン）
    → 位置情報・通知の権限リクエスト
    → ホーム

[一般ユーザー ホーム（タブ構成。下部6タブ、内「近く」に4セグメント）]
  1. 近く（デフォルト）
     - 切替: [募集] [人] [店] [施設]
     - 募集: アクティブな募集カード（距離・残り時間・人数・ジャンルタグ・主催者の嗜好）
     - 施設: 近くのゲームセンター・公民館・集会所一覧（「Googleマップで開く」「この施設で募集」）
     - 「募集をかける」フローティングボタン
  2. 部屋（チャット一覧）
  3. コミュニティ（＋イベント・オフ会企画）
  4. ゆずりあい（ゲームグッズのゆずる・探す・交換の登録・検索と完了管理。金銭取引は行わない）
  5. 探す（興味カテゴリで近くの人・店舗・コミュニティを探す）
  6. マイページ（プロフィール編集、設定、招待、ブロック管理）

[募集フロー]
  募集作成 → 投稿 → 近くの人に表示
  閲覧者が「参加したい」→ 主催者に通知 → 承認 → グループチャット生成
  期限到来 → 自動消滅

[ビジネスユーザー ホーム]（v1.5）
  ダッシュボード（AI接客応答数 / 来店傾向） / 店舗ページ編集 / AI接客の設定 / 地図連携設定 / プラン管理
```

## 9. KPI

| フェーズ | KPI |
|---|---|
| 起動初期（0〜3ヶ月） | 週次アクティブユーザー（WAU）、募集投稿数/日、募集あたり応募数、「施設」タブ→募集作成の転換率 |
| 定着（3〜6ヶ月） | 募集成立率（投稿→チャット生成）、成立後チェックイン率、リピート仲間率（同一ユーザーと2回以上）、ゆずりあい完了数/月 |
| 収益化（6ヶ月〜） | ビジネスユーザー数（ゲームセンター・ゲーム教室等）、AI接客経由来店数、解約率、LTV |

初期はジャンルの近さよりも「募集あたり応募数」が最重要。1.0を下回る場合、リリース地域を都市部のゲームセンター密集エリアに絞る。

## 10. カテゴリ拡張戦略

第1弾「飯とも」〜第12弾「ゲーとも！」で共通のプラットフォーム（認証・募集・コミュニティ・地図連携・ビジネス課金）が確立できた。総合版（本アプリ）はこれらを**ハブ（HubConfig）として1本にまとめ**、新しい趣味は（a）ユーザー投票（Phase 2）で需要を確認して運営が正式ハブ化する、（b）UGCハブ（Phase 3）としてユーザーが申請し運営が審査して追加する、の2経路で拡張する。アプリの再開発・再リリースは原則不要になる。
